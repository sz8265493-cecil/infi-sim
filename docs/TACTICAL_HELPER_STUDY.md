# Tactical_Helper 军表实现学习记录

日期：2026-10-29。参考：JFungx/Tactical_Helper，使用此前获准查看并保存于工作区的源码快照；本次没有拉取远端，不能视为其最新版本评审。仅记录结构与行为结论，不复制私有源码。

## 已对照的部分

- army-list-official-codec：官方可变长整数、UTF-8、Base64与URL输入，以及真实跨阵营代码测试。
- army-list-schema：版本化军表、稳定条目身份、配置快照、精简持久化数据。
- army-list-resolver：关联单位展开、配置解析、includes附属模型、官方数据更新差异。
- army-validator：按组位置占用、点数、SWC成本与奖励、尉官、未解析配置等校验。
- army-list-service与army-list-codec：解析/存储/云同步分层；自有分享格式与官方Army格式分离。

## 应用于模拟器的判断

1. 保留独立编解码器；借鉴真实军表测试集合的覆盖思路，区分协议支持、阵营目录支持、局内规则支持三种能力，不因代码可解析就宣称可对局。
2. 当前三个官方ID精确匹配与重复匹配拒绝策略继续保留。参考快照resolver存在仅optionId回退和缺ID时首配置回退，模拟器不能沿用，以免更换武器或技能。
3. 持久化军表应与局内单位实例分开：稳定entryId关联保存数据，导入时再生成棋子状态，避免战损/剩余弹药污染原始军表。
4. 数据版本升级应先展示配置名称、点数、SWC及装备变化；失配条目保留并阻止开始，不能静默删除或替换。目前仅有armyRef版本信息，不等于已有完整升级差异界面。
5. 应将位置占用、随行/附属模型、名单行数分别统计；当前Ancillary局中部署支持不代表所有多形态/多附属都已支持。
6. 后续校验宜输出带类型、组号、条目ID的结构化问题，再由UI渲染；维持现有错误与能力警告区分，避免泛化为全部合法。
7. 自有分享码必须与官方Army码有清楚格式标识。只有官方格式能够表达的字段才导出为官方码；火力组、教学配置、局内状态不能伪装成官方信息。
8. 云同步和删除墓碑机制可作为未来多设备军表库参考；现阶段静态Pages站点不因此引入后端或复制其云服务。

## 后续实施优先级

- 第一优先：配置数据升级差异与稳定条目身份；结构化导入诊断。
- 第二优先：关联模型和名单位置占用的精确映射，补充分组/导出再导入的一致性测试。
- 第三优先：军表库与对局存档分离，自有格式互操作；需要时再设计云同步。
